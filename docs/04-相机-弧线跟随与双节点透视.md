# 04 · 相机：弧线跟随与双节点透视

沿用 `silkyscene@1`：中心为 0，+X 右，+Y 上，1 u = 1080 设计 px。相机节点的 `target` 写 `"camera"`。

## 1. 2D 相机（默认）

```json
"camera": { "projection": "orthographic", "target": { "x": 0, "y": 0, "z": 0 },
  "yaw": { "rad": 1.5707963267948966, "cycles": 0 }, "pitch": { "rad": -1.5707963267948966, "cycles": 0 },
  "roll": { "rad": 0, "cycles": 0 }, "distance": 10, "focal": 1, "zoom": 1 }
```

（用 `createSceneBuilder` 时这些默认值自动补齐，只需 `b.camera({ zoom, target })`。）

- 节点：`target.x`、`target.y`、`zoom`。**zoom 独立控制**，不由距离换算；推拉建议 `interpolation: "log"`（对数插值，视觉匀速、永远为正）。
- 两层：**目标点（look）** 是相机「想看」的点；**取景（frame）** 决定真正的画面中心。默认同步（`lag: 0`）；写 `lag` 时取景晚出发、沿同样的弧线在节点结束时追上。相机矩阵只由取景层计算。

| 需求 | 写法 | 说明 |
| --- | --- | --- |
| 移镜带一点弧度 | 不写 | 默认 arc 0.15，向上弯，lag 0 |
| 某次移镜要直线 | 节点上 `arc: 0` | 逐点等于直线插值 |
| 整个项目都直线 | `camera: { …, arc: 0 }` | 相机级默认 |
| 延迟跟随 | 节点或相机上写 `lag`（建议 0.15–0.4 s） | 取景晚于目标点，节点结束时到位 |
| 取景追赶的速度感不同 | `followEase` | 只影响取景层 |
| 缩放晚一拍 | zoom 节点上写 `lag` | 默认 0 |
| 弧线让画面露出区域外 | 减小 arc、改 arcSide，或调 `camera.maxOvershoot`（默认 48 px） | 准备阶段逐帧检查，超限报错带时间 |

- **为什么默认向上弯**：摇臂运镜的惯例是横移时机位中段最高；相机的「容器」是整个世界，「背离容器中心」对它没有意义。主体在画面下半部时，建议换 `arcSide` 或减小 arc。
- 参数建议：arc 0.05–0.2（> 0.25 横移会「飘」）；lag 默认 0；maxOvershoot 24–96 px。

## 2. 双节点透视相机（可选）

像 AE 的双节点相机：手写**目标点** x / y / z（看哪里）和**摄像机** x / y / z（站在哪里）；俯仰、偏转、视线距离全部由「摄像机 → 目标点」几何推出，不手写。

- `camera.view3d.distance`（u，必填）：焦距 D。摄像机在目标点正上方、高度 = D 时，画面与 2D 逐像素一致。
- `camera.view3d.maxTilt`（度，默认 35）：推导出的 |俯仰|、|偏转| 上限，逐帧检查。
- `camera.position {x, y, z}`：摄像机起始位置；不写时默认在目标点正上方，z = target.z + D。
- `camera.approach {x, y}`：靠拢偏移（默认 0）。
- 节点：`target.x / y / z`、`position.x / y / z`、`approach.x / y`、`zoom`（投影之后的额外 2D 缩放）。position / approach 不支持 lag：要「后动」就把 `at` 写晚。
- 元素可以写 `z`（u，朝向观众为正，经过组逐级相加）获得视差。

### 2.1 推导

- 摄像机 `P = position.xy + approach.xy`（z = position.z），目标点 T，`d = P − T`，视线距离 `L = |d|`，要求 d.z > 0。
- `pitch = asin(−n.y)`、`yaw = atan2(n.x, n.z)`，n = d / L。摄像机在目标点左侧 → yaw < 0；在下方 → pitch > 0；正上方 → 都为 0。
- 目标点永远在画面中心；画面在目标点处的缩放 = zoom × D / 视线到 z = 0 平面的长度。
- `scene.camera` 仍是 2D 取景矩阵，3D 只体现在 `scene.view3d` 与图元的 `transform3d`（单应矩阵 → CSS `matrix3d`）。推导出的俯仰、偏转为 0 时直接走 2D 代码。

### 2.2 重叠运镜，不做硬停（核心写法）

**不要**把「移过去」和「归回垂直」写在同一条 `position` 轨道上：两段首尾相接时速度在交界掉到 0，画面像停了一下。拆成两个**可时间重叠**的控制组，线性相加：

```text
P.xy = position.xy + approach.xy
```

- 主移镜用 `position.*`，只走 60–80% 的路程，与 `target.*` 同时起步；
- `approach.*` 在主移镜途中提前启动、与后半段重叠，一直滑到目标点正上方（俯仰 / 偏转 → 0°），默认 `arc: 0`。

```js
// 官方样片 topology-flow：推向根因节点（root 在 x = -0.95）
k(12.5, "camera", "target.x",   2.5, -0.6,        { ease: IN_OUT })
k(12.5, "camera", "position.x", 2.5, -0.6 * 0.75, { ease: IN_OUT })          // 跟 75%
k(13.3, "camera", "approach.x", 2.2, -0.6 * 0.25, { ease: IN_OUT, arc: 0 })  // 晚 0.8 s 起步，补完 25%
k(12.5, "camera", "zoom",       2.6, 0.78,        { ease: IN_OUT, interpolation: "log" })
k(12.5, "camera", "position.z", 2.6, 1.62,        { ease: SOFT })
```

### 2.3 报错（带时间）

- 写 position 前没声明 `camera.view3d`；双节点与显式 `view3d.pitch / yaw / height` 同时写（二选一）。
- 推导出的俯仰或偏转超过 maxTilt；摄像机 z ≤ 0 或不高于目标点。
- 元素四角在相机平面上或身后（透视因子 ≤ 0）。

### 2.4 已知局限

- 遮挡按文档顺序，不按 z 排序；文字倾斜后会轻微发软；HUD 不参与 3D；世界遮罩仍是屏幕空间渐变。
- 摄像机 x / y 弧线需要两轴同时写；z 只有直线补间。

## 3. 镜头节拍建议

- **一镜到底**：画面中心对准当前讲述的焦点；换段用推拉 / 横移，少切硬镜。
- **停留拍要呼吸**：停住时保留轻微推拉（zoom ±1–3%），避免完全死停。
- **重叠起步**：下一段移镜在上一段尾部开始，不要等上一段完全停住。
- 起幅略松（zoom 0.92–1.0）→ 强调短推 → 换焦点 → 收幅回到总结卡、approach 归零。

## 4. 检查器

- 世界视图：青色圆点 = 目标点（青色线 = 目标点轨迹 / 弧线），墨色方块 = 摄像机，细线 = 视线；方块旁标「摄像机 · z · 俯仰 · 偏转 · 距离」（推导值）。
- 时间轴相机行分组：目标点 x / y / z、摄像机 x / y / z、靠拢目标 x / y、缩放 zoom；默认「仅摄像机」轨道，便于核对移镜是否连续。
- 相机面板列出每段移动的 arc、lag 各级声明值与解算值，以及目标点 / 取景两行时间条。
