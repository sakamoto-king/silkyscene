# SilkyScene 当前设计基线：画布与稳定布局

状态：当前重写基线

日期：2026-08-11

## 1. 目标

SilkyScene 首先要成为一套稳定的 Web 画布布局运行时。

它允许设计者先固定构图，再替换文字、图片或其他素材。素材自身尺寸可以变化，但运行时应依据设计规则重新解算内容，使元素仍处于预期位置并维持预期的视觉占比。

当前第一目标不是动画效果，也不是复刻完整 CSS，而是建立一条确定的布局链路：

```text
设计声明 → 画布选择 → 布局解算 → 确定几何 → 渲染输出
```

动画只消费布局结果，不参与布局求解。

## 2. 当前确认的设计决策

### 2.1 画布先于元素

每个 Presentation 必须先定义画布。画布至少包含：

- 设计比例，例如 `16:9` 或 `9:16`
- 宿主区域中的适配方式
- 可选的响应式布局变体

元素的百分比坐标相对于画布内容区域，而不是浏览器整个 viewport。

### 2.2 元素拥有独立于素材的布局声明

元素由“内容”和“布局”组成。内容可以替换，布局声明保持不变。

```js
{
  type: "text",
  content: "可替换文字",
  layout: {
    anchor: [0, 0],
    left: "10%",
    top: "10%",
    width: "30%",
  },
}
```

运行时可以读取素材的天然尺寸或文字测量结果，但这些数据只能参与元素内部的适配计算，不能无规则地反向改变画布构图。

### 2.3 锚点负责连接“元素自身”与“画布位置”

`anchor` 使用归一化坐标：

| 值 | 含义 |
| --- | --- |
| `[0, 0]` | 元素左上角 |
| `[0.5, 0.5]` | 元素中心 |
| `[1, 1]` | 元素右下角 |

`left` 和 `top` 定义锚点在画布中的位置。

因此：

```js
{
  anchor: [0, 0],
  left: "10%",
  top: "10%",
}
```

表示把元素左上角放在画布的 `(10%, 10%)`。

这里的 `anchor` 是几何定位参考点，不等同于文字的 `text-align`。

### 2.4 百分比使用对应画布轴作为基准

- `left`、`width` 相对于画布宽度。
- `top`、`height` 相对于画布高度。
- 锚点始终使用元素自身宽高的归一化坐标。

例如在最终像素画布为 `1920 × 1080` 时：

```js
{
  left: "10%",
  top: "10%",
  width: "30%",
}
```

得到的位置参考值为 `x = 192px`、`y = 108px`，目标宽度为 `576px`。

### 2.5 默认等比尺寸模式只接受一个尺寸轴

默认模式用于保持内容自身比例：

- 可以指定 `width`
- 或者指定 `height`
- 不能同时指定二者

未指定的一轴由内容测量结果与目标轴等比计算。

同时传入 `width` 和 `height` 时，v0 设计倾向于直接报错，避免系统悄悄拉伸素材或引入不明确的裁切行为。未来如需要固定矩形，可显式增加另一种 `box` 布局模式，而不是改变默认语义。

### 2.6 响应式首先由画布条件驱动

同一 Presentation 可以提供多个布局变体：

```js
{
  canvas: {
    default: { aspectRatio: "16:9" },
    variants: {
      portrait: { when: { aspectRatio: "9:16" } },
      ultraWide: { when: { minAspectRatio: "21:9" } },
    },
  },
}
```

当前优先级：

1. 画布比例条件
2. 画布方向条件
3. 必要时再加入画布像素宽高条件，例如 `minWidth: 1920`

这是画布级响应式，不是让每个元素直接监听浏览器 viewport。

## 3. 建议的运行时边界

### 3.1 Definition

保存设计者输入：画布、元素内容、百分比布局、锚点和响应式变体。

### 3.2 Measure

获得内容的天然几何信息：

- 图片和视频的 intrinsic width / height
- 文字在明确字体、字号、字距、行高与换行规则下的测量结果
- 图形或路径的本地 bounds

测量结果是布局输入，不是最终布局。

### 3.3 Resolve

根据当前画布和布局变体，把相对声明解算为不可含糊的数值结果：

```js
{
  rect: { x, y, width, height },
  anchor: { x, y },
  transform: { x, y, scaleX, scaleY, rotation },
}
```

Resolve 应尽量保持纯计算。相同画布、相同内容测量和相同声明必须得到相同结果。

### 3.4 Render

DOM、SVG、Canvas 或 WebGL 后端只消费 Resolved Scene，不重新解释百分比、响应式条件或素材布局规则。

### 3.5 Motion

动画层只处理两个已解算状态之间的变化：

```text
Resolved State A → Resolved State B
```

自研动画还是 GSAP 属于 Motion Backend 决策，不影响 Definition、Measure 和 Resolve。

## 4. 文字元素的当前边界

文字是稳定布局中最需要单独设计的元素，因为文字没有像图片那样天然、固定的长宽比。不同文本、字体和换行都会改变测量结果。

当前可以确认：

- 文字的位置由锚点和画布百分比决定。
- 替换文字不能无规则地移动其他元素。
- 字体加载完成后才能得到可信的测量结果。
- 默认等比模式只接受 `width` 或 `height` 一轴。

尚未决定：

- 多行文字是否允许自动换行。
- 指定宽度后是缩放整个文字块，还是保持字号并重新排版。
- 文字超过目标区域时采用 `clip`、`shrink`、`ellipsis` 还是报错。
- 是否需要分别提供标题模式与段落模式。

这些问题应通过真实版式样例验证后再形成 API，不在当前基线中假定答案。

## 5. 画布适配仍需确定的问题

画布设计比例与宿主容器比例不一致时，需要明确外层适配策略。候选包括：

- `contain`：完整显示设计画布，允许留黑边或空白边。
- `cover`：铺满宿主区域，允许裁切画布边缘。
- `stretch`：拉伸画布，不推荐作为默认值。

当前倾向使用 `contain` 作为默认方向，但尚未固化为实现契约。

还需要后续确定：

- 布局变体切换是离散切换还是允许插值。
- 画布安全区是否是一等概念。
- 字号、描边、圆角等非位置尺寸以宽、高、短边还是画布对角线为百分比基准。
- 响应式条件冲突时的优先级和继承规则。

## 6. 当前非目标

- 不在这一阶段决定 GSAP 或自研动画引擎。
- 不以旧版 Scene API 兼容为设计前提。
- 不实现完整 CSS Flexbox、Grid 或浏览器排版规范。
- 不迁移或复核上一阶段全部文档。
- 不把 DOM 当作布局事实来源。

## 7. 第一阶段的可验证成果

重写的第一个里程碑应当是一个静态布局原型，而不是动画 Demo：

1. 定义 `16:9` 与 `9:16` 两个画布配置。
2. 放置文字、图片和矩形三种元素。
3. 使用锚点、百分比位置和单轴尺寸完成布局。
4. 替换不同长宽比图片和不同长度文字。
5. 验证布局解算结果稳定且可重复。
6. 输出静态 DOM 或 SVG 画面。

只有静态布局契约稳定后，才进入场景状态与动画执行层。
