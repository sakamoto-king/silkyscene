# SilkyScene 与 Remotion 的分工、最小样例（讨论稿）

状态：早期讨论稿（已归档）· 日期：2026-10-10

> 归档说明：后来的结论是视频导出由 SilkyScene 自带（`player.html` + `export:mp4`，见 [06](../06-视频导出与HyperFrames接入.md)），不依赖 Remotion。本文保留当时的分工思考。

当前坐标契约见 [01 设计基线](../01-设计基线与项目愿景.md)。`silkyscene@1` 使用中心为零、右和上为正的世界坐标。适配器消费解算后的设计像素和相机矩阵。

## 1. 对当前状态的理解

- **已实现**：ResolvedScene 类型（rect / text / line）+ DOM/SVG 混合渲染器 + playground（直接喂已解算的几何）。
- **只有占位**：definition / measure / resolve / render 四个阶段。
- **设计基线**：00 画布与稳定布局、01 混合渲染与遮罩。
- **愿景**：02，项目文档作为一等产品，代码、编辑器和 AI 都操作同一份文档。
- **历史文档**：其余文档描述旧 API，不作为当前契约。

## 2. 分工建议

```
Project Document（JSON / TS）── AI 与人编辑的对象
        ↓ definition → measure → resolve      ← SilkyScene 核心（纯函数、确定性）
   ResolvedScene（每个状态一份）
        ↓ 动画：状态 A → 状态 B 的插值，只是时间 t 的纯函数
  ┌─────┴───────────────┐
  ↓                     ↓
浏览器演示运行时        Remotion 适配器
（翻页、交互、讲解）     （逐帧渲染 → MP4，配音乐、字幕、实拍）
```

- **SilkyScene 负责**：画布、稳定布局、可替换内容、场景状态，以及 AI 可编辑的文档结构。这一层 Remotion 没有，也是这个项目的核心价值。
- **Remotion 负责**：逐帧、可复现的视频导出，以及音频、实拍素材合成和预览 Studio。SilkyScene 不另写视频导出和时间轴渲染器。
- **约束**：动画必须是“时间 → 画面”的纯函数，可以任意跳到某一帧。这正是 Remotion 的要求，也和“动画消费确定几何”的基线一致。

## 3. 最小可验证样例（建议）

1. 一份场景文档：一个标题、一行副标题、一条线，提供 16:9 和 9:16 两个画布变体，两个状态（入场前 / 入场后）。
2. resolve 用纯 TS 实现，可在 Node 中跑单元测试：同输入得同几何；替换更长的标题后，锚点和宽度不变。
3. 同一份 ResolvedScene：
   - (a) 在 playground 中作为可翻页的演示播放；
   - (b) 在 Remotion composition 中按帧插值，渲染成 MP4。
4. 验收：只改文档里的文字（模拟 AI 编辑），两种输出构图都不乱；MP4 可以任意跳帧。

## 4. 待讨论

- 文字测量（换行、溢出）放在哪里执行。浏览器和 Remotion 都运行在 Chromium 中，可以共用一套测量。
- 动画描述（缓动、错峰）是否也做成文档的一部分，供 AI 编辑。
- Linux 与 Windows 开发环境的依赖目录分开。
