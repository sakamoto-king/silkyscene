# 01 · 设计基线与项目愿景

SilkyScene 是一套**以画布为先**的 Web 场景引擎：先固定构图，再把文字、图片等素材放进去；素材尺寸变了，运行时按设计规则重新解算，构图不乱。几何确定之后，再交给确定性的运动引擎——同一份场景既能在浏览器里**现场步进演示**，也能**逐帧导出 MP4**（双模合一，见 [05](./05-检查器-现场演示与场景构建.md)、[06](./06-视频导出与HyperFrames接入.md)）。

## 1. 一条确定的链路

```text
设计声明 → 测量（字体 / 图片天然尺寸）→ 布局解算 → 确定几何 → 渲染（DOM + SVG）
                                         ↑
                    时间轴只改「声明值」，每一帧都是 renderAt(t) 的纯函数
```

- **Definition**：画布、区域、元素内容、布局声明、相机、节点（cue）。`parseProject` 严格校验，未列出的字段一律报错。
- **Measure**：文字在明确字体、字号、字距、行高下的测量；图片的天然宽高。测量是布局输入，不反向改变构图。
- **Resolve**：把百分比、锚点、组嵌套、相机解算成不含糊的数值（层像素框 + 变换矩阵）。相同输入必得相同输出。
- **Render**：渲染器只消费解算结果，不再解释百分比或响应式规则。
- **Motion**：动画层只在两个已解算的声明状态之间插值，不参与布局求解。

## 2. 坐标契约 `silkyscene@1`（硬契约）

| 约定 | 值 |
| --- | --- |
| 原点 | 画布中心 `(0, 0)`；+X 向右，+Y **向上** |
| 单位 | `1 u = 1080` 设计像素；默认画幅 1920 × 1080（宽 ≈ 1.778 u） |
| 区域 | `x / y` 是区域中心的世界坐标；元素 `x / y` 相对所属容器中心 |
| 百分比 | 相对所属容器的整轴；位置边缘为 **±50%**，尺寸 100% = 占满 |
| 锚点 | `layout.anchor` 与连线端点 `at` 用框内中心坐标 `[-1, 1]`：`[-1, 1]` 左上、`[0, 0]` 中心、`[1, -1]` 右下 |
| ID | 区域、组、元素、`camera`、`screen` 共用一个命名空间，**全局唯一** |
| 相机 | `target (0,0)`、`zoom 1`、`roll 0` 时取景恰好覆盖全画幅；正 roll 相机顺时针转 |

世界点到设计像素：`(960 + X × 1080, 540 − Y × 1080)`。旧版 `@0` 文档（Y 向下、0–100% 边缘）先用 `node tools/migrate_scene_v0_to_v1.mjs` 迁移。

## 3. 元素 = 可替换内容 + 不变的布局声明

```json
{ "id": "title", "kind": "text", "text": "可替换文字", "fontSize": 0.05, "color": "#0C0C0C", "align": "left",
  "layout": { "region": "main", "anchor": [-1, 1], "x": "-40%", "y": "40%", "width": "30%" } }
```

- 锚点负责把「元素自身的哪个点」放到「容器里的哪个位置」；它是几何参考点，不等于 `text-align`。
- 图片默认等比：`width` 与 `height` 只写一个，另一轴按内容比例推出；矩形、组需要两轴都写。
- 字体加载完成后才有可信的测量；检查器、演示页、帧页共用同一套字体加载流程。

## 4. 项目愿景

- **项目文档是一等产品**：稳定的 schema 版本、人和 AI 都能读写的结构化 JSON、可 diff、可迁移、素材引用与结构分离。
- **同一份文档，多种入口**：TypeScript API、场景构建器 `createSceneBuilder`、检查器、AI 编码代理，最终都落到同一份 `silkyscene@1` JSON，并经过同一个严格校验器。
- **本地优先**：项目文件能下载、能放进 Git、能在本地仓库里预览和导出；云端服务只做增值，不锁文件。
- **AI 友好**：严格校验 + 逐帧质量检查（`check_scene`）给出带时间点的中文报错，让 AI 编码代理能自我修正，而不是生成一段不可继续编辑的 HTML。

## 5. 非目标

- 不复刻完整 CSS Flexbox / Grid 或浏览器排版规范。
- 不把 DOM 当作布局事实来源（DOM 只是渲染输出）。
- 不用逐帧采样的关键帧冒充动画设计（见 [02 §6](./02-混合渲染与图元规范.md)）。

## 6. 仍在探索

- 画布适配策略（`contain` / `cover`）与安全区是否成为一等概念。
- 多行文字的换行与溢出策略（`clip` / `shrink` / `ellipsis`）。
- 画布级响应式变体（16:9 / 9:16）切换是离散还是可插值。
