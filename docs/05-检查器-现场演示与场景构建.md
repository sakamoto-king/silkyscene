# 05 · 检查器、现场演示与场景构建

> **双模合一 = 现场步进演示 `present.html` + 确定性视频导出 `player.html` / `export:mp4`。**
> 同一份 `<name>.scene.json` + `<name>-timing.json`：现场汇报时在浏览器里按键翻页讲，会后一行命令导出 MP4 分享。两种输出逐帧一致，因为它们都只调用 `prepared.renderAt(t)`。

## 1. 文件与入口

每个场景是一对文件，放在 `playground/`：

| 文件 | 内容 |
| --- | --- |
| `<name>.scene.json` | `silkyscene@1` 场景文档（画布、区域、元素、相机、节点） |
| `<name>-timing.json` | 锚点名 → 秒；可选 `segments`（讲稿段落）、`steps`（演示停靠点） |

起服务：`npm run dev`（Vite，`127.0.0.1:5311`）。三个页面：

| 页面 | 地址 | 用途 |
| --- | --- | --- |
| 检查器 | `/playground/inspector.html?doc=<name>` | 三栏检查、世界俯视图、逐帧对照声明值 / 解算值、编辑数值与时间 |
| 现场演示 | `/playground/present.html?doc=<name>[&step=n]` | 全屏步进翻页汇报 |
| 帧播放页 | `/playground/player.html?doc=<name>[&t=秒]` | 无 UI、确定性逐帧，供视频导出与 HyperFrames 捕获 |

不写 `doc` 时三页都打开官方样片 `topology-flow`。

## 2. 场景构建器 `createSceneBuilder`

手写 JSON 容易漏字段、ID 重名、锚点对不上。推荐用构建器写一个 `.mjs` 生成脚本：

```js
import { createSceneBuilder, px } from "@silkysite/scene"   // 仓库内用 "../../dist/index.js"

const b = createSceneBuilder({ background: "#FAFAF8" })      // 也可传 camera / motion / worldMask
b.region("world", { x: 0, y: 0, width: 6, height: 3.4 })
b.group("card", { in: "world", w: 0.6, h: 0.3 }, { opacity: 0 })
b.rect("card-bg", { in: "card", w: "100%", h: "100%" }, { fill: "#FFFFFF", radius: px(16) })
b.text("card-t", { in: "card" }, "标题", { fontSize: px(40), weight: 700 })
b.cue("card-in", 0.4, "card", "opacity", 0.5, 1, { ease: "ease-out" })
b.step("open", 1, "开场")
const { scene, timing } = b.build()                          // 严格校验 + 编译时间轴，失败立即抛错
```

| 方法 | 说明 |
| --- | --- |
| `region(id, {x, y, width, height})` | 区域（u） |
| `rect / text / group / path / dots / image / null(id, place, …)` | `place = { in, x, y, w, h, anchor }`；`in` 是容器（区域、组或 `"screen"`） |
| `text(id, place, text, props)` | 默认 `color #0C0C0C`、`align center` |
| `line(id, [from, at], [to, at], props)` | 端点挂元素；`width` 单位 u，常用 `px(2)`–`px(3)` |
| `camera(patch)` | 合并到默认正交相机 |
| `anchor(name, time)` | 登记锚点；同名不同时刻会抛错 |
| `cue(at, time, target, property, duration, to, opts)` | 同时登记锚点与节点；`opts` 可带 `ease / arc / arcSide / lag / interpolation / path / bakedReason` |
| `segment(name, start, end, text)` | 讲稿段落（检查器时间轴显示） |
| `step(id, at, title)` | 演示停靠点 |
| `build()` | 返回 `{ scene, timing }`；跑 `parseProject` + `compileTimeline` |

- `px(n) = n / 1080`：把设计像素换成 u。
- ID 重名、使用保留名 `camera` / `screen`、锚点冲突在调用时就抛错；字段拼错、单位不一致在 `build()` 抛错。
- 小技巧：用同一时刻共享一个锚点名（样片里的 `keyer`：`t08.00`），检查器里拖一个锚点就整拍平移。

## 3. 现场演示 `present.html`（步进翻页）

- **停靠点**来自 timing.json：优先 `steps`，没有就用 `segments` 的起点，再没有就用全部锚点（含 0）。场景自然时长超过最后一个停靠点时，自动追加一个「结束」步（不计页码）。
- **步进语义**：按「下一步」从当前停靠点以 1× 速度正放，到下一个停靠点**精确停住**；过渡中再按一次，先跳到目标停靠点，再继续往下一步（连按不会丢步）。「上一步」以同样速度**平滑倒放**回上一个停靠点。
- **停靠点写在「这一页动画播完、画面落定」的时刻**：停住时画面就是这一页的完成态，标题与之对应。

| 操作 | 键位 |
| --- | --- |
| 下一步 | `→` `↓` `Space` `PageDown` `Enter`、点击画面、向左滑 |
| 上一步 | `←` `↑` `Shift+Space` `PageUp` `Backspace`、向右滑 |
| 第一 / 最后一步 | `Home` / `End` |
| 跳到第 n 步 | `1`–`9` |
| 全屏 | `F` |
| 隐藏 / 显示控制条 | `H` |

- 界面：右上角极简胶囊控制条 `02 / 05 · 标题 · 进度点 · [‹] [›] [全屏]`，2.5 s 无操作自动淡出，鼠标一动就回来；顶部 2 px 进度线。
- 检查器顶栏的「现场演示 ↗」直接在新标签打开当前场景的演示页。
- 程序接口：`createDeckController(steps)` / `deckSteps(timing, duration)` / `deckKeyAction(key, shift)`（`@silkysite/scene` 导出），可以嵌进你自己的页面。演示页在 `window.__silkyDeck` 上暴露控制器，`<html data-step data-moving data-ready>` 便于自动化测试。

## 4. timing.json

```json
{ "t00.40": 0.4, "t02.00": 2,
  "segments": [{ "name": "s1", "start": 0, "end": 4.5, "text": "很多人每天列十几条待办……" }],
  "steps": [{ "id": "list", "at": 2.6, "title": "清单越列越长" }] }
```

- 顶层只放「锚点名 → 有限数字」，外加保留键 `segments`、`steps`。
- 读取一律用 `parseTiming(json)`（返回 `{ anchors, segments, steps, ignored }`）或 `timingAnchors(json)`；**不要** `new Map(Object.entries(json))`——会把数组塞进锚点表。
- 改时间只动 timing，不要把秒数写死进 scene；检查器拖动关键帧后「导出时间表」会原样保留 `segments` / `steps`。

## 5. 硬校验 `check_scene`

```bash
node tools/check_scene.mjs <name...>            # 解析 + 逐帧解算 + 逐帧轨迹 lint + 画面质量
node tools/check_scene.mjs --strict <name...>   # 质量警告也算失败
```

1. `parseProject` 严格校验、`prepareProject` 逐帧解算（越界、zoom ≤ 0、文字撞框）。
2. `lintScene`：0 条未报备的逐帧采样轨迹。
3. `qualityScan` 画面质量（持续 ≥ 0.25 s 才报）：
   - **small-text**：屏幕实测字号 < 13 px（`--min-font` 改阈值）——写场景时请保证 **≥ 14 px**；
   - **edge-clip**：可见的文字 / 卡片（不透明度 > 0.5、面积 ≤ 35% 画幅）被取景框边缘切掉一部分。
4. 通过时打印检查器链接；`--fps` 改采样帧率（默认 30）。

## 6. 检查器

- **三栏**：左侧场景结构树（相机、区域、元素，绘制顺序）；中间世界俯视图 + 画中画（相机真实画面）；右侧属性面板（声明值 / 解算值对照、矩阵、相机推导值、当前节点与缓动曲线）。
- **世界俯视图**：画布中心为原点，u 与设计 px 双单位；取景框、目标点（青色）、摄像机（墨色方块）、弧线与视线、空对象十字、区域边界，图层可开关。
- **时间轴**：「仅摄像机」（默认）/「选中元素」/「全部轨道」；讲稿段落与演示停靠点显示为刻度，点一下跳过去；方向键逐帧。
- **编辑模式**：改数值、改缓动 x1..y2 与 arc、拖关键帧（同组锚点一起平移、按帧取整），失焦即重新解算，出错自动撤回；「导出 JSON」「导出时间表」保存。
- 「复制本帧数据」输出 `silkyscene-inspector-frame@2`：原始矩阵、四角、测量、声明与当前状态。
- URL 参数：`doc`、`frame`、`select`、`tracks`、`panels` / `left` / `right`、`dur`。
- 字体放在 `_storage/inspector-fonts/`（HostGrotesk-Bold、InstrumentSans-VF、GeistMono-VF、NotoSansSC-VF，不入库），缺失时回落系统字体。

## 7. 五分钟写一份现场汇报

1. **列页**：每页一句话，想好每页停住时画面上有什么。
2. **写生成脚本** `playground/examples/weekly.mjs`：

```js
import { writeFileSync } from "node:fs"
import { createSceneBuilder, px } from "../../dist/index.js"

const FONT = "Noto Sans SC, sans-serif"
const OUT = { type: "cubicBezier", x1: 0.22, y1: 1, x2: 0.36, y2: 1 }
const MOVE = { type: "cubicBezier", x1: 0.65, y1: 0, x2: 0.35, y2: 1 }
const b = createSceneBuilder({ background: "#FAFAF8" })
b.region("world", { x: 0, y: 0, width: 6, height: 3.4 })

// 第 1 页：标题
b.text("title", { in: "world", y: 0.06 }, "本周进展", { fontSize: px(72), weight: 700, fontFamily: FONT })
b.text("sub", { in: "world", y: -0.06 }, "三件事 · 一个风险", { fontSize: px(30), color: "#64748B", fontFamily: FONT })
// 第 2 页：三张卡片在右边，镜头横移过去
;["上线新检查器", "导出提速 3×", "文档重写"].forEach((t, i) => {
  b.group("card" + i, { in: "world", x: 1.9, y: 0.3 - i * 0.3, w: 0.9, h: 0.22 }, { opacity: 0 })
  b.rect("card" + i + "-bg", { in: "card" + i, w: "100%", h: "100%" }, { fill: "#FFFFFF", stroke: "#DCE1E8", strokeWidth: px(1.5), radius: px(16) })
  b.text("card" + i + "-t", { in: "card" + i }, t, { fontSize: px(34), weight: 600, fontFamily: FONT })
})
// 第 3 页：风险
b.text("risk", { in: "world", x: 1.9, y: -0.62 }, "风险：周三前要定接口", { fontSize: px(30), color: "#D97706", opacity: 0, fontFamily: FONT })

b.cue("go", 0.2, "camera", "target.x", 1.4, 1.9, { ease: MOVE, arc: 0 })
;[0, 1, 2].forEach(i => b.cue("card-" + i, 0.8 + i * 0.15, "card" + i, "opacity", 0.5, 1, { ease: OUT }))
b.cue("risk", 2.0, "risk", "opacity", 0.5, 1, { ease: OUT })
b.cue("risk", 2.0, "camera", "zoom", 0.8, 1.12, { ease: OUT, interpolation: "log" })
b.cue("risk", 2.0, "camera", "target.y", 0.8, -0.3, { ease: OUT, arc: 0 })
// 停靠点 = 每页落定的时刻
b.step("cover", 0, "本周进展").step("done", 1.9, "完成了什么").step("risk", 2.8, "风险")

const { scene, timing } = b.build()
writeFileSync(new URL("../weekly.scene.json", import.meta.url), JSON.stringify(scene, null, 1))
writeFileSync(new URL("../weekly-timing.json", import.meta.url), JSON.stringify(timing, null, 1))
```

3. **生成并自检**：`npm run build && node playground/examples/weekly.mjs && node tools/check_scene.mjs --strict weekly`
4. **排练**：`npm run dev`，打开 `http://127.0.0.1:5311/playground/present.html?doc=weekly`，按 `F` 全屏，`→` 翻页。
5. **会后导出**：`npm run export:mp4 -- weekly` → `_storage/exports/weekly.mp4`。
